# ModSwap Integration Guide

Backend (Firebase) + Frontend (Flutter UI by your friend) integrated together.

## Architecture Overview

```
┌──────────────────────────────────────────┐
│  AuthGate                                │
│  ───────────                             │
│  Watches AuthProvider state, decides    │
│  which screen to show:                   │
│                                          │
│  • initializing      → Splash            │
│  • unauthenticated   → LoginScreen       │
│  • emailUnverified   → VerifyEmailScreen │
│  • profileIncomplete → CompleteProfile   │
│  • authenticated     → MainNavigation    │
└──────────────────────────────────────────┘
              ↑
              │ watches
              │
┌──────────────────────────────────────────┐
│  AuthProvider (state management)         │
│  ───────────                             │
│  • Listens to Firebase Auth state        │
│  • Fetches profile from Backend          │
│  • Computes status                       │
│  • Exposes: register, login, logout,     │
│    completeProfile, resendEmail, etc.    │
└──────────────────────────────────────────┘
              ↓ uses
┌──────────────────────────────────────────┐
│  Services Layer                          │
│  • AuthService → Firebase Auth           │
│  • DioClient → HTTP w/ token + logging   │
│  • ApiService → Backend API calls        │
└──────────────────────────────────────────┘
```

## Setup Instructions

### Step 1: Replace files in `lib/`

```bash
unzip modswap_integrated.zip
cp -r modswap_integrated/lib/* /path/to/flutter_project/lib/
cp modswap_integrated/pubspec.yaml /path/to/flutter_project/pubspec.yaml
```

⚠️ Don't replace the `images/` folder — keep your friend's assets.

### Step 2: Install dependencies

```bash
cd /path/to/flutter_project
flutter pub get
```

### Step 3: Configure Firebase

```bash
flutterfire configure
```

Select project `modswap-7b425` and choose platforms.

This creates `lib/firebase_options.dart` automatically.

### Step 4: Update Project ID (if different)

Edit `lib/config/api_config.dart`:

```dart
static const String projectId = 'modswap-7b425';  // ← your project
```

### Step 5: Run

```bash
# Terminal 1 — Backend Emulator
cd /path/to/modswap_backend/functions
npm run serve

# Terminal 2 — Flutter
cd /path/to/flutter_project
flutter run -d chrome
```

## Testing the Integrated Flow

### Flow 1: New user — full path

1. App opens → AuthGate sees no user → **LoginScreen** (friend's UI)
2. Click "Register" → **RegisterScreen** (friend's UI)
3. Fill email + password + confirm + check Terms → "Register"
4. Backend trigger creates profile in Firestore
5. Email verification sent (in emulator: link in terminal logs)
6. **Modal "Check Your Email"** with branded styling
7. Click OK → auto-logout → back to LoginScreen
8. Login with same credentials
9. AuthGate sees `emailUnverified` → **VerifyEmailScreen** (new, branded)
10. Either:
    - Click verification link from email → screen auto-detects
    - Or in Emulator UI toggle "Email verified" manually
11. AuthGate sees `profileIncomplete` → **CompleteProfileScreen** (new, branded)
12. Fill Display Name + Student ID + Faculty + Line ID → "Save & Continue"
13. AuthGate sees `authenticated` → **MainNavigation** (friend's bottom nav)
14. Navigate to Menu tab → see profile + logout button

### Flow 2: Returning user

1. App opens → AuthGate restores session
2. If verified + complete → straight to MainNavigation
3. If not verified → VerifyEmailScreen
4. If incomplete → CompleteProfileScreen

### Flow 3: Block non-KMUTT email

1. Register with `hacker@gmail.com` → Frontend validation blocks
2. If bypassed via Emulator UI → Trigger deletes user within 2 seconds

## Why AuthGate Pattern?

Without AuthGate, every screen would need to:
- Check if user is logged in
- Check if email is verified
- Check if profile is complete
- Navigate manually

With AuthGate, **state changes automatically reflect in UI**:
- User logs out anywhere → instantly back to LoginScreen
- Email gets verified → instantly moves to CompleteProfile
- Profile gets completed → instantly enters MainNavigation

This is the same pattern used by production apps (Instagram, Twitter, etc.).

## Why Provider?

AuthProvider holds the auth state in one place, so:
- Any screen can access it via `context.watch<AuthProvider>()`
- AuthGate reactively rebuilds when state changes
- No prop drilling
- Easy to test (mock AuthProvider in tests)

## Troubleshooting

### "Cannot connect to server"
- Check Backend Emulator is running on port 5001
- Check `projectId` in `api_config.dart`

### "Email not verified" loop after clicking link
- The screen auto-checks every 3 seconds
- Or click "I've Verified My Email" button manually

### Firebase emulator complains about Java
- Install Java 21: `brew install openjdk@21`

### Hot reload doesn't update auth state
- This is normal — Provider rebuilds work fine on hot reload
- If broken, do hot restart (Shift+R)
