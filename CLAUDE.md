# ModSwap — Project Memory

## Project Overview
**ModSwap** is a KMUTT-exclusive student marketplace app for swapping and selling second-hand items. Only `@mail.kmutt.ac.th` email addresses are allowed. Built with Flutter (mobile + web) and Firebase backend.

## Tech Stack

| Layer | Technology |
|---|---|
| Frontend | Flutter 3.x (Dart), Material 3 |
| State Management | Provider 6.x (ChangeNotifier) — migrating to Riverpod 2.x |
| Navigation | Manual Navigator.push — migrating to GoRouter |
| HTTP Client | Dio 5.x with auth interceptor |
| Backend | Firebase Cloud Functions (TypeScript + Express) |
| Database | Cloud Firestore (NoSQL) |
| Auth | Firebase Authentication (Email/Password) |
| Storage | Firebase Storage |
| AI/Search | Gemini embedding-001 (semantic search, 768-dim vectors) |
| Image | flutter_image_compress + cached_network_image |

## Screens & Flows

1. **Auth Flow**: Login → Register → VerifyEmail → CompleteProfile
2. **Home Flow**: Home (browse + semantic search + category filter)
3. **Listing Flow**: ListingDetail → PostItem (create/edit)
4. **My Items Flow**: MyItems (draft/published/sold states)
5. **Social Flow**: Wishlist, Notifications, Rating, EditProfile, ChangePassword

## Architecture (Current)

Service-layer pattern — **not yet Clean Architecture**. Migration is in progress.

- `providers/` — ChangeNotifier classes (AuthState, ThemeProvider, NotificationProvider)
- `services/` — Firebase/API wrappers (AuthService, ApiService, ListingsService, etc.)
- `models/` — Plain Dart data classes
- `screen/` — UI screens that consume providers via `context.read/watch`

**Target**: Strict Clean Architecture with Domain / Data / Presentation layers.

## Auth Flow (AuthStatus enum)

```
initializing → unauthenticated → emailUnverified → profileIncomplete → authenticated
```

- Email must match `@mail.kmutt.ac.th`
- Custom Firebase claims: `{ role: "student", kmutt: true }`
- Backend validates token on every API request via `authMiddleware`

## Firestore Collections

| Collection | Description |
|---|---|
| `users/{uid}` | Profile + denormalized stats (rating, totalReviews, totalTrades) |
| `listings/{id}` | Items with title, images, category, price, condition, state, embedding |
| `deals/{id}` | Swap/sale transaction records |
| `pendingRatings/{id}` | Rating prompts (buyer → seller) |
| `users/{uid}/notifications/{id}` | Real-time notifications |
| `users/{uid}/devices/{id}` | Registered devices |
| `users/{uid}/wishlist/{id}` | Saved listings |

## Conventions

- **File naming**: snake_case for files, PascalCase for classes
- **Screens**: suffix `_screen.dart`
- **Widgets**: reusable components in `widgets/` subdirectory by feature
- **Models**: always include `fromJson`, `toJson`, `copyWith`
- **API calls**: always go through `ApiService` → `DioClient` (never call Dio directly from screens)
- **Error handling**: catch at service layer, surface via `_errorMessage` in providers
- **Emulator**: `ApiConfig.useEmulator` flag controls local vs. production Firebase
- **Language**: UI text in Thai, code comments may be Thai

## Environment & Secrets

- Firebase config: `lib/firebase_options.dart` (generated by FlutterFire CLI — **do not edit manually**)
- Backend secrets: must be in `.env` file, **never hardcoded in Dart or TypeScript source**
- Emulator ports: Auth 9099, Firestore 8080, Functions 5001, Storage 9199

## Feature Flags

Managed via **Firebase Remote Config**. Current flags:

| Flag Key | Default | Description |
|---|---|---|
| `enable_semantic_search` | `true` | Enables Gemini AI semantic search on home screen |

Rollback plan: set flag to `false` in Firebase Console → app falls back to keyword-only search within 60 seconds (Remote Config fetch interval).

## DO-NOT-DO List

- **NEVER** commit secrets, API keys, or `.env` files to the repository
- **NEVER** set Storage Rules to `allow read, write: if true` in production
- **NEVER** skip Firebase ID token verification on backend endpoints
- **NEVER** allow non-KMUTT emails to register (enforced at client + backend trigger + Firestore rules)
- **NEVER** call Firestore or Firebase Auth directly from screen widgets — always go through service/provider layer
- **NEVER** use `Navigator.push` in new code — use GoRouter (migration in progress)
- **NEVER** add new ChangeNotifier providers — use Riverpod (migration in progress)
- **NEVER** delete the `users/{uid}` document directly — only the backend `on-user-create` trigger manages user lifecycle
- **NEVER** expose `debugPrint` statements in production builds — use structured logging
- **NEVER** add unbounded `ListView` without pagination

## Agent Workflow

This project uses multi-agent orchestration via Claude Code. See `.claude/agents/` for role definitions.

**Delegation order:**
1. **Architect** — design and plan (Plan Mode, read-only output)
2. **Flutter Engineer** — implement the plan
3. **QA Engineer** — write and run tests
4. **Security Reviewer** — audit changes (read-only, never writes code)

Complex tasks must go through Plan Mode before implementation. The agent that writes code must not be the agent that approves it.
